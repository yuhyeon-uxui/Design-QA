# Design QA 2차 개선 로드맵 (Phase 2 Roadmap)

## 📌 비전 (Vision)
단순한 버그 리포팅 및 코멘트 게시판을 넘어, **'디자이너와 프론트엔드 개발자의 완벽한 브릿지(Bridge) 플랫폼'**으로 진화.
범용 프로젝트 관리 툴(Redmine, Jira 등)의 무거운 워크플로우를 지양하고, **시각적 직관성(Visual-first)**과 **마찰 없는 빠른 QA(Low-friction)**에 집중함.

---

## 🚀 1. Figma API 연동: 인앱 데브모드 (In-App Dev Mode)

### 💡 아이디어 개요
- 피그마 API를 활용하여 레이어, 텍스트, 색상, 좌표 정보를 추출해 QA 보드 내에서 직접 **Figma Dev Mode**와 같은 개발 스펙을 제공하는 기능.
- 회사의 디자인 시스템 컴포넌트가 완벽하게 구축되어 있지 않더라도, 화면에 그려진 날것(Raw)의 수치(폰트 크기, 패딩, 갭, 컬러코드 등)를 그대로 가져와 활용 가능.

### 🎨 예상 UX / UI
- **분할 탭 인터페이스:** 
  - 현재의 `[ QA 이슈 상세 (Pin) ]` 우측 패널 상단에 탭을 추가하여 `[ 💬 이슈 & 코멘트 ]` 탭과 `[ 📐 디자인 속성 (Dev Mode) ]` 탭으로 분리.
- **클릭 앤 뷰 (Click & View):**
  - 사용자가 'Figma 시안 (Expected)' 이미지 위에서 특정 텍스트나 박스 요소를 마우스로 클릭.
  - 우측 패널이 `[ 📐 디자인 속성 ]` 탭으로 전환되며 클릭한 요소의 실제 CSS 값(margin, padding, font-size, HEX color 등) 즉시 출력.
- **스마트 워크플로우 (Smart Workflow):**
  - 개발자가 디자인 스펙을 직관적으로 확인한 후, 즉시 `[ 💬 이슈 & 코멘트 ]` 탭으로 돌아가 "여백 24px로 피그마와 동일하게 수정 완료" 등의 코멘트를 남기며 QA 사이클을 매우 빠르게 종결.

### 🛠 기술적 고려사항
- **좌표 변환 알고리즘 (Coordinates Mapping):** 업로드된 실제 스크린샷 이미지의 픽셀 좌표와 Figma 캔버스의 절대 좌표 간의 비율(Scale) 변환 및 정확한 맵핑 로직 필요.
- **Figma API 응답 파싱 (Data Parsing):** Figma REST API의 방대한 JSON 트리 구조(Node Tree)에서 사용자가 클릭한 지점에 위치한 최하단(Leaf) 노드 또는 유의미한 컨테이너 노드를 정확히 탐색해내는 깊이 우선 탐색(DFS) 로직 구현 필요.

## 🚀 2. AI 기반 QA 대시보드 및 푸시 알림 정책 도입

### 💡 아이디어 개요
- 단순 통계를 보여주는 것을 넘어, **AI(Gemini)가 프로젝트의 병목 지점을 분석하고 일정 리스크를 관리**해주는 시스템 구축.
- 외부 메신저(Slack, Notion) 연동 없이 툴 내부(In-App)에서 개발팀과 디자인팀의 업무 싱크를 맞출 수 있는 **스마트 알림(Notification) 센터** 마련.

### 🎨 예상 UX / UI
- **도움말 옆 종 모양(🔔) 알림 센터:**
  - GNB 우측 상단에 알림 아이콘 배치. AI가 일정 위험이나 상태 변경을 감지하면 빨간색 배지(Badge) 점등.
- **AI QA 분석 리포트 전용 카드:**
  - 대시보드 통계 카드 영역에 `[✨ AI QA 리포트]` 카드를 추가하여, 팀 전체의 에러 패턴, 병목 화면, 협업 팁 등을 모달/새 탭에서 시각적으로 제공.
- **마감일 분리 표시 (Dev Due / QA Due):**
  - 깃랩 연동을 고려하여 `개발 수정 마감일`과 `최종 디자인 QA 마감일`을 분리하여 프로젝트 카드에 노출.

### 📋 알림(Notification) 발생 정책
알림 피로도를 줄이기 위해 꼭 필요한 '액션 유도형' 및 '경고형' 알림만 선별.

1. **마감일 임박 경고 (D-1):**
   - 개발/QA 마감일이 24시간 남았으나 미해결(Open) 이슈가 있을 때 발생.
2. **병목(Bottleneck) 방치 경고:**
   - 3일 이상 아무런 상태 변화 없이 방치된 이슈가 존재할 때 발생.
3. **Re-open(잦은 반려) 핑퐁 경고:**
   - 동일 이슈가 디자이너에 의해 3회 이상 반려(Re-open)되었을 때 소통(허들) 권장 알림 발생.
4. **올 클리어(All Clear) 축하:**
   - 100% 이슈가 해결 처리(Resolved)되었을 때 발생.
5. **깃랩(GitLab) 양방향 동기화 알림 (Webhook):**
   - 개발자가 깃랩에 코드를 푸시하거나 이슈를 Closed 했을 때 QA 툴로 즉각 알림.
   - 디자이너가 QA 툴에서 반려(Re-open) 시 깃랩으로 즉각 알림.
