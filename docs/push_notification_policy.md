# 푸시 알림 정책 (Push Notification Policy)

## 📌 개요
디자인 QA 툴 내부에서 사용자의 피로도를 최소화하고, 반드시 필요한 액션을 유도하기 위한 인앱(In-App) 스마트 알림 정책입니다. 외부 메신저(Slack, Notion) 연동 없이 자체 GNB의 '종 모양(🔔) 알림 센터'를 통해 제공됩니다.

---

## 🔔 발생 정책 (Notification Rules)

### 1. 🚨 마감일 임박 경고 (Deadline)
- **발생 조건:** 프로젝트의 [개발 수정 마감일] 또는 [최종 QA 마감일]이 **24시간 이내(D-1)**로 도래했으나, 미해결(Open) 상태인 이슈가 1개 이상 존재할 때.
- **알림 메시지:** `🚨 [프로젝트명] 마감일이 하루 남았습니다! (미해결 이슈 N건)`
- **타겟 유저:** 해당 프로젝트 참여자 전체 (디자이너, 개발자)

### 2. ⚠️ 병목(Bottleneck) 방치 경고
- **발생 조건:** 특정 이슈가 생성되거나 마지막 상태가 변경된 후, **3일 이상 아무런 업데이트 없이 방치**되었을 때.
- **알림 메시지:** `⚠️ [프로젝트명] 3일 이상 방치된 이슈가 N건 있습니다. 담당자 확인이 필요합니다.`
- **타겟 유저:** 해당 이슈 담당자(Assignee) 및 프로젝트 관리자

### 3. 🔥 잦은 반려(Re-open) 핑퐁 경고
- **발생 조건:** 디자이너가 개발자의 작업물을 확인하고 **'다시 수정 요청(Re-open)'을 3회 이상 반복**한 이슈가 발생했을 때.
- **알림 메시지:** `🔥 [프로젝트명] 특정 이슈의 수정 요청이 3회 반복되었습니다. 개발팀과 디자인팀의 싱크(허들)를 권장합니다.`
- **타겟 유저:** 해당 이슈 담당 디자이너 및 개발자

### 4. ✅ 올 클리어(All Clear) 축하 알림
- **발생 조건:** 특정 프로젝트의 모든 이슈가 100% '해결(Resolved)' 처리되었을 때.
- **알림 메시지:** `🎉 [프로젝트명] 모든 개발 수정이 완료되었습니다! 디자이너의 최종 검수를 진행해 주세요.`
- **타겟 유저:** 프로젝트 참여 디자이너

### 5. 💻 깃랩(GitLab) 양방향 동기화 알림 (Webhook 기반)
- **발생 조건 (개발자 ➡️ 디자이너):** 개발자가 깃랩에 코드를 푸시하거나, 이슈 상태를 Closed로 변경했을 때.
- **알림 메시지:** `✅ [프로젝트명] OOO 개발자님이 이슈를 해결 처리했습니다. 재검수를 진행해 주세요.`
- **발생 조건 (디자이너 ➡️ 개발자):** 디자이너가 QA 툴에서 상태를 반려(Re-open)했을 때.
- **알림 메시지:** `💡 [프로젝트명] 디자이너님이 이슈를 반려(Re-open)했습니다.`

---

## 🗑 데이터 보관 및 삭제 정책 (Data Retention)
- **자동 삭제 (TTL 90일):** 모든 푸시 알림(Notification) 내역은 서버 DB 최적화 및 보안을 위해 **발생일 기준 90일이 지나면 자동으로 영구 삭제**됩니다.
