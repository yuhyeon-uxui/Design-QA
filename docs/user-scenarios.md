# 디자인 QA 보드 (Design QA Hub) - 사용자 시나리오

## 1. 서비스 목적
단순히 개발 요청서를 만드는 도구를 넘어, 여러 팀(디자인, 개발, 기획, QA, 다국어/운영)이 함께 확인하고 이슈의 상태를 관리할 수 있는 **협업형 디자인 QA 보드**. 피그마 시안 혹은 실제 캡처 이미지를 바탕으로 직관적인 위치 기반(핀) QA를 가능하게 함.

## 2. 주요 사용자 및 니즈
- **디자인팀**: "디자인 기준과 다르게 구현된 부분을 캡처 위에 핀으로 콕 집어 명확히 전달하고 싶다."
- **개발팀**: "텍스트 설명만으로는 위치를 찾기 어려우니, 무엇을 어떻게 수정해야 하는지 화면 내 정확한 위치와 설명으로 확인하고 싶다."
- **기획/PM**: "오픈 전 전체 QA 이슈의 상태(진행률)와 우선순위를 한눈에 파악하고 싶다."
- **QA팀**: "수정 완료된 항목들만 필터링해서 빠르게 재검수하고 최종 승인하고 싶다."
- **운영/다국어팀**: "국가별 텍스트 깨짐, 번역 적용 상태 등을 분리해서 확인하고 싶다."

## 3. 메인 시나리오 흐름
1. **프로젝트 생성**: QA 담당자가 프로젝트(예: `인바운드 웹사이트`, `동호회 서비스 앱`)를 선택하고 플랫폼, 회차 등을 설정하여 생성.
2. **화면(이미지) 등록**: 캡처 이미지나 피그마 시안 캡처를 업로드하고, 화면명과 디바이스 정보를 등록.
3. **직관적 핀 찍기**: 업로드된 화면 위에서 이슈가 발생한 위치를 클릭하면 번호 핀(1, 2, 3...)이 순차적으로 생성됨.
4. **이슈 내용 입력**: 핀 번호와 매칭되는 입력 폼에 이슈 유형(레이아웃, 컬러 등), 문제 내용, 수정 요청사항, 중요도, 담당팀 등을 기입.
5. **팀별 상태 관리**: 
   - 개발팀: 해당 핀 위치와 내용을 확인하여 코드 수정 후 `수정완료` 처리.
   - QA/디자인팀: `수정완료` 건을 재검수하여 `완료` 처리 혹은 `이슈발생`으로 반려.
6. **내보내기 (Export)**: 기존 업무 프로세스 유지를 위해 전체 내역을 지정된 엑셀 양식으로 다운로드하여 공유 및 보관.
