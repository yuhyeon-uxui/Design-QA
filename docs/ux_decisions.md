# UX 의사결정 기록 (UX Decisions)

이 문서는 프로젝트를 진행하며 발생한 주요 이슈와, 이를 해결하기 위한 UX적 의사결정(Trade-off 및 솔루션) 과정을 기록합니다.

---

## 1. 개발자 협업을 위한 피그마-실제화면 비교 뷰 도입

### 🤔 배경 및 문제 제기 (개발자 실무 피드백)
- 프론트엔드 개발자가 디자인 QA를 처리할 때는 단순히 "텍스트로 된 수정 요청사항"만 보고 작업하는 것이 불가능합니다.
- 실무에서는 **"피그마 화면(CSS 수치 확인용)"**과 **"실제 테스트 앱 화면"**을 직접 비교하고, 차이가 있으면 코드를 수정하는 방식으로 작업합니다.
- 만약 QA 보드가 '캡처 이미지'만 덩그러니 제공한다면, 개발자는 정확한 수치를 찾기 위해 결국 피그마를 다시 열고 해당 화면을 직접 검색해야 하는 큰 번거로움(Context Switching)이 발생합니다. 이로 인해 "차라리 피그마에 댓글을 남기는 게 실무적으로는 편하다"는 피드백이 제기되었습니다.

### 💡 해결 방안 (UX 솔루션 적용)
단순히 피그마 댓글 기능으로 돌아갈 경우, 기획/QA팀 관점에서의 진행률 트래킹, 엑셀 추출, 상태 관리가 불가능해집니다. 따라서 Design QA Hub 내에서 개발자의 니즈를 충족시키는 방향으로 UX를 개선하기로 결정했습니다.

1. **스플릿 뷰 (Side-by-Side Comparison)**
   - 가장 핵심 화면인 'QA 보드'의 좌측 이미지 영역을 분할하여, **[피그마 시안 이미지]**와 **[실제 구현 캡처 이미지(핀 표기)]**를 나란히 띄워줍니다.
   - 이를 통해 개발자는 듀얼 모니터 없이도 한 화면에서 "시안과 구현의 차이"를 즉각적으로 비교할 수 있습니다.

2. **피그마 프레임 딥링크 (Deep Link to Figma)**
   - 단순히 프로젝트 전체 피그마 주소만 두는 것이 아니라, 이슈 폼 내부에 **해당 화면의 특정 피그마 프레임(Node ID)으로 바로가는 버튼**을 큼직하게 배치합니다.
   - 개발자가 픽셀 수치를 봐야 할 때 클릭 한 번으로 피그마 Inspect 뷰로 직행하도록 돕습니다.

### 🚀 향후 고도화 예정 사항
- **오버레이 슬라이더 (Opacity Diff)**: 두 이미지를 겹쳐두고 투명도를 조절하는 슬라이더를 제공하여, 1~2px 어긋난 마진/패딩을 시각적으로 명확히 잡아낼 수 있는 기능.
- **Figma Plugin 개발**: QA 보드에서 등록된 이슈 핀을 피그마 플러그인을 통해 피그마 캔버스 위에 실시간 동기화하여 보여주는 궁극적인 협업 환경 구축.

## 2. QA 진행률 표기 정책 (Progress Calculation)

### 🤔 고민 배경
- **화면 기준 계산의 한계:** 총 2장의 화면 중 1장은 '완료', 1장은 핀이 100개 찍힌 '미완료' 상태일 때 50%로 표기되면 이슈의 리스크(핀 개수)가 묻히는 문제.
- **핀 기준 계산의 한계:** 완벽하게 디자인되어 수정할 곳이 없는 화면은 핀이 0개이므로, 화면 검수라는 수고로움이 진행률(0%)에 전혀 반영되지 않는 모순 발생.

### 💡 결정된 정책: 하이브리드 점수 방식 (Hybrid Score)
- **화면 검수**와 **이슈 해결**을 모두 각각의 독립된 '태스크'로 인정하고 합산하여 계산합니다.
- **계산식:** `(완료된 화면 장수 + 완료된 핀 수) / (전체 화면 장수 + 전체 핀 수) * 100`
- **효과:** 완벽하게 통과된 화면의 수고로움도 인정하면서, 이슈(핀)가 많은 화면의 리스크도 동시에 반영하여 대시보드와 QA 보드의 진행률 수치를 100% 동일하게 동기화했습니다.

## 3. 미작성 화면 이탈 방지 정책 (Exit Warning Policy)

### 🤔 고민 배경
- QA 보드에서 모든 화면을 확인하지 않고 대시보드로 돌아가려 할 때 어떻게 처리할 것인가?
- **초기 방안:** "머무르기"와 "나가기" 선택지를 주어 유저의 통제권(퇴근 등)을 보장. (Soft Warning)
- **동료 협의 결과:** QA 누락을 원천 차단하기 위해 **강제로 모든 화면을 작성(혹은 삭제)해야만 나갈 수 있도록 막자(Hard Block)**는 결론 도달.

### 💡 결정된 정책: 가이드 이동 방식 (Guided Resolution)
- 단순하게 "안 됩니다"라고 길을 막고 알아서 찾게 하는 불친절한 Hard Block 대신, 시스템이 미작성 화면으로 알아서 안내해 주는 UX로 디벨롭.
- **플로우:**
  1. 사용자가 `< (뒤로 가기)` 버튼 클릭.
  2. 미작성 화면(확인 대기)이 남아있다면 1버튼 알럿 팝업 노출.
     - 팝업 내용: *"아직 확인 대기 중인 화면이 남아있습니다. QA를 모두 완료해야 나갈 수 있습니다."*
  3. 유저가 팝업의 **`[다음 미작성 화면으로 이동]`** 버튼을 클릭하면, 남은 미작성 화면 중 가장 첫 번째 화면으로 자동 포커스 이동.
  4. 해당 화면을 완료 후 다시 나가기를 누르면, 시스템이 또다시 **그다음 미작성 화면으로 이동**시킴.
- **효과:** 미작성 화면이 여러 개 남았더라도 팝업 버튼만 누르면서 '도장 깨기' 하듯 자연스럽게 남은 업무를 100% 클리어하도록 부드럽게 강제(Nudge)할 수 있습니다.
